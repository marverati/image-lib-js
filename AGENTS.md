# AGENTS.md

Notes for coding agents working in this repo. The README has the user-facing overview; this file covers what you need to change things safely.

## What this is

- A TypeScript library for per-pixel image editing: `src/image-lib.ts` (the `ImageLib` helpers and the pixel map types) and `src/PixelMap.ts` (the generic base class).
- A browser editor built on the library: `src/editor/`. Users write JavaScript snippets that call a small global API (`gen`, `filter`, `copy`, `use`, `param.slider`, ...). That API lives in `src/editor/editingApi.ts` and is put on `window` in `src/editor/editor.ts`.
- Older demo pages in `src/demo/`, runnable Node example scripts in `src/examples/`, and helpers in `src/utility/`.

Bundling uses Parcel 1 (`parcel-bundler`), with no framework. There is no backend in this repo: login and server storage talk to an external service, and public scripts are fetched from `rationaltools.org`.

## Setup

```sh
npm ci
```

`canvas` (node-canvas) is an optional dependency. It lets the library render in Node, and some unit tests and the `src/examples/` scripts need it. If it failed to install, the canvas unit tests are skipped locally. In CI they are required.

## Running tests

Run both suites after making changes. Both have to pass before you push.

```sh
npm test            # Jest unit tests (about 2 s)
npm run test:e2e    # Playwright e2e tests against the editor (about 1 min)
npm run test:all    # both
```

- Unit tests live next to the code in `src/**/test/*.test.ts`. Jest only looks in `src/`.
- E2E specs live in `e2e/*.spec.ts`, with shared helpers in `e2e/helpers.ts` (`editorPage`, `typeAndRun`, `getCanvasPixel`, ...). Playwright starts the dev server itself (`npm run dev:editor` on port 1234) and reuses a running one locally.
- Run a single file with `npx jest src/test/ImageLib.test.ts` or `npx playwright test e2e/editing-api.spec.ts`.
- **Browser missing?** Run `npx playwright install chromium`. If you can't download browsers (for example in a sandbox), but some Chromium is installed, point Playwright at it:
  `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chrome npm run test:e2e`
  (on Claude Code web: `/opt/pw-browsers/chromium`).
- `e2e/scripts-smoke.spec.ts` runs every built-in example and every public script and fails on any console error. If you change the editor API, this test tells you which existing scripts you broke. Public scripts are served from the local `src/editor/share_internal/` during this test, not from the live site.

CI (`.github/workflows/tests.yml`) runs both suites on every push and pull request.

## Other useful commands

```sh
npm run dev:editor       # editor at http://localhost:1234, regenerates the example JSON first
npm run build:editor     # standalone build in dist/editor/
npx ts-node src/examples/example_gen_perlin.ts   # Node example, writes output/result.png
```

`npx tsc --noEmit` currently reports errors in a few `src/examples/example_combine_*.ts` files. Those errors were there before; don't worry about them unless you touch those files. Just don't add new ones.

## Things to know before changing code

- **Generated files:** `src/editor/examples_raw.json` and `src/editor/public_examples.json` are generated by `npm run process-examples` from `src/editor/examples_raw.js` and `src/editor/share_internal/*.js`. Edit the sources, then regenerate. `dev:editor` and `build:editor` regenerate them automatically. The JSON files are committed.
- **Pixel values:** colors are `[r, g, b, a]` arrays with every channel in 0–255, alpha included. `ImageLib.generate`/`filter`/`combine` choose the map type from what the callback returns (a 4-array gives RGBA, a 3-array RGB, a number grayscale, a boolean `BoolPixelMap`).
- **`get(x, y)` samples.** It accepts fractional and out-of-range coordinates and applies the wrap mode (default `"initial"`, which returns the map's initial value) and the interpolation mode (default `"bilinear"`). Use `getFast` for plain integer reads inside the image.
- **In-place vs buffered filtering:** `filter` modifies in place, while it reads, so a filter that looks at neighbouring pixels needs `filterBuffered`. The editor's `filter()` already uses the buffered version.
- **Browser and Node:** the library must keep working in both. Node-only packages are loaded with `eval('require')` in `src/image-lib.ts`, so Parcel doesn't try to bundle them. Don't replace that with a plain `import`/`require`.
- **Line endings:** `.gitattributes` says LF, but `src/image-lib.ts` is committed with CRLF. Keep the existing line endings of any file you edit, so the diff doesn't turn into a whole-file rewrite.
- **Documentation for users:** if you change the snippet API, also update the help overlay (`src/editor/documentation.ts`), the LLM prompt template (`src/editor/prompt-template.md` / `.txt`) and the README.

## Style

- TypeScript, 4-space indentation in most files (some tests use 2), double quotes in library code, single quotes common in tests and e2e specs. Match the file you're in.
- Comments are sparse and explain *why*. Keep them that way.
- Add tests for new library behaviour in `src/test/`, and for new editor behaviour in `e2e/`. The e2e tests check actual pixel values wherever they can.
